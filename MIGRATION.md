# Upgrade to fork version 4

This major release incorporates upstream through `79793b2` (Laravel support, native enum helpers, modern exception setup and optional AI skill installers) and retains fork behavior. The local upstream merge is `d9f559a687803ae8b6cd473043f631459f6d8d4d`.

1. Use PHP 8.2-8.5 and Laravel 12/13; Laravel 13 needs PHP 8.3+. The package now explicitly requires Laravel's full framework and a compatible current Guzzle major. Duster and its unused tooling are replaced with Pint and Larastan/PHPStan. Development resolves current PHPUnit 13 on PHP 8.4+, with compatible PHPUnit 11/12 for older maintained PHP.
2. Keep the Composer name `essa/api_tool_kit`. Configure your fork VCS/release repository; upstream Packagist does not automatically publish fork versions. No package-name migration is performed.
3. Replace the removed upstream `Exceptions\Handler` integration with `APIToolKit::registerExceptionRenderers()` in `bootstrap/app.php`'s `withExceptions` callback. Database errors now return 500; database and HTTP 5xx details remain hidden outside explicitly enabled non-production debug mode. Prepared HTTP statuses and headers are preserved.
4. New package configuration uses native `GeneratorFilesType` enum backing values as keys (`->value`). Merge published config/stubs deliberately. The legacy fork `Enum` class and scalar Eloquent casts remain, while new enums use Laravel's `make:enum` and optional `EnumHelpers`. Strict value checks no longer coerce unrelated scalar types.
5. Generated models remain **unguarded** by owner choice, with the fork's casts/relationship/model scaffolding. Generated controllers use validated data, including the mode without generated FormRequests. Review application authorization and fields before exposure.
6. Generation preserves existing source by default; `--force` explicitly regenerates it. Rendered PHP is syntax-checked. Failed runs attempt to restore planned files and report restoration failures; route blocks replace in place, and an existing create migration is reused. Do not overwrite migrations already executed in a deployed application; create an evolution migration instead. Restore routes now use POST, so update clients when regenerating routes.
7. Schema parsing preserves simple enum values (letters, digits, underscores and hyphens, optionally surrounded by matching quotes), normalizes `int`/`varchar`/`datetime`, supports numeric Blueprint arguments and multiple modifiers, and orders nullable foreign-key modifiers before `constrained()`. Unsafe enum punctuation and malformed type/name fragments are rejected before generation. Use an explicit application migration for richer enum values. Review aliases/options against your database rather than treating the DSL as arbitrary SQL.
8. Custom filter hooks must be public, non-static, one-argument `void` methods outside base infrastructure. Keep non-filter helpers non-public. Malformed request arrays produce validation errors and invalid page sizes use a safe positive default. Query strings survive pagination.
9. `MediaHelper::disk()` now returns an isolated `MediaStorage`, not a globally configured `MediaHelper`. Update explicit type hints. Static calls always use the default disk. Base64 input must be a matching raster-image data URI; corrupt base64/non-images/SVG and file-name traversal are rejected, and storage failures throw.
10. `ConsumesExternalServices` follows upstream's new five-argument HTTP-client signature. It receives one data array and a request JSON/form flag, returns decoded JSON, and uses `PendingRequest` for the authorization hook. Update old seven-argument query/form/raw-response callers and old reference-mutating authorization hooks. Redirects are rejected; retry properties remain explicit opt-in.
11. Permission generation no longer reads a missing template or duplicates CSV rows. The restore ability is `restore`. Existing workflow/knowledge files remain unless a reviewed `--force` is provided to the AI installer; unrelated global instruction sections are preserved. Optional bundled rules are application guidance, not runtime configuration.

Generated artifacts are application-owned and are not overwritten automatically by Composer installation. Compare custom stubs with the shipped versions, regenerate into a reviewable branch, run migrations/tests on your application database, and validate your routes/authentication policies before deployment. Package verification uses SQLite and isolated local consumers; it does not certify an application's live infrastructure.
